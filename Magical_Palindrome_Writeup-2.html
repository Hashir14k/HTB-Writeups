Synopsis (!)

The challenge presents a Node.js web application behind nginx that accepts a JSON payload with a palindrome field. The server runs a palindrome validation function that requires input length ≥ 1000 and checks every character is a string and satisfies palindrome symmetry. However, nginx enforces a strict 75-byte body limit (client_max_body_size 75), blocking a naive 1000-character string.

To solve the challenge, the player must leverage JavaScript type coercion: by sending palindrome as a JSON object with keys "0" and "NaN" (rather than a string), the .length property resolves to undefined, which bypasses the undefined < 1000 comparison. Meanwhile, Array(undefined) yields a single-element array, the loop runs exactly once, and obj[undefined - 0 - 1] resolves to obj["NaN"], satisfying the palindrome check. The function returns null and the flag is revealed.

The critical file is app/index.mjs. The flag is read from /flag.txt and returned only when IsPalinDrome(palindrome) returns null: 

import {serve} from '@hono/node-server';
import {serveStatic} from '@hono/node-server/serve-static';
import {Hono} from 'hono';
import {readFileSync} from 'fs';

const flag = readFileSync('/flag.txt', 'utf8').trim();

const IsPalinDrome = (string) => {
    if (string.length < 1000) {
        return 'Tootus Shortus';
    }

    for (const i of Array(string.length).keys()) {
        const original = string[i];
        const reverse = string[string.length - i - 1];

        if (original !== reverse || typeof original !== 'string') {
            return 'Notter Palindromer!!';
        }
    }

    return null;
}

const app = new Hono();

app.get('/', serveStatic({root: '.'}));

app.post('/', async (c) => {
    const {palindrome} = await c.req.json();
    const error = IsPalinDrome(palindrome);
    if (error) {
        c.status(400);
        return c.text(error);
    }
    return c.text(`Hii Harry!!! ${flag}`);
});

Understanding the Two Gates

The IsPalinDrome function imposes two gates the input must pass:

Gate Condition How to Pass Fail Response
Gate 1 string.length < 1000 .length must be ≥ 1000 OR the comparison must yield false (e.g., undefined < 1000 = false) Tootus Shortus
Gate 2 original !== reverse || typeof original !== 'string' Every indexed value must be a string and equal its symmetric counterpart Notter Palindromer!!

nginx Body Size Constraint

From config/nginx.conf: 

server {
    listen 80;
    server_name 127.0.0.1;
    client_max_body_size 75;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_read_timeout 5s;
    }
}

This means any JSON body larger than 75 bytes is rejected with 413 Request Entity Too Large. A 1000-character palindrome string (at least ~1017 bytes with JSON wrapping) is impossible to send directly. The player must find a compact payload that satisfies both gates.

Solution (!)

Finding the vulnerability (*)

The root vulnerability is missing input type validation. The IsPalinDrome function never checks that its string argument is actually a JavaScript String. When the JSON body is parsed, the palindrome field can be any valid JSON type — string, number, boolean, array, or object.

Core Insight: For JavaScript objects and numbers, .length is undefined. And undefined < 1000 evaluates to NaN < 1000, which is false — Gate 1 is bypassed without needing 1000+ characters!

Next, we examine what happens in the for loop when string.length is undefined:

  • Array(undefined) — since undefined is not an integer, the Array() constructor creates [undefined] (a 1-element array).
  • The .keys() iterator yields only 0 — the loop runs exactly once with i = 0.

In that single iteration:

const original = string[0];                   // obj["0"]
const reverse  = string[undefined - 0 - 1];     // obj[NaN] → obj["NaN"]

JavaScript coerces NaN to the string "NaN" when used as a property key. So obj[NaN] resolves to obj["NaN"]. If we craft a JSON object with both "0" and "NaN" keys set to the same string value, the loop passes!

The Attack Step by Step

Let us consider our attack scenario:

  1. Identify the constraint: nginx enforces client_max_body_size 75, blocking any payload over 75 bytes.
  2. Analyze the validation logic: The IsPalinDrome function has two gates — a length check and a character-by-character palindrome check — but never validates that the input is actually a string.
  3. Find the type-confusion bypass: If palindrome is an object, .length is undefined, and undefined < 1000 is false — Gate 1 bypassed in 0 bytes of payload length.
  4. Exploit Array(undefined): Creates [undefined] (1 element), so the loop runs once. obj[undefined - 0 - 1] = obj[NaN] = obj["NaN"].
  5. Craft the payload: {"0":"a","NaN":"a"} — only 37 bytes total, well under the 75-byte limit. Both indexed values are strings and equal.
  6. Send and capture the flag: The function returns null, the server responds with "Hii Harry!!! HTB{...}".

Getting the flag (!)

A final summary of all that was said above:

  1. The IsPalinDrome function does not validate that its input is a String type.
  2. Passing a JSON object with keys "0" and "NaN" exploits:
    • obj.length = undefined → undefined < 1000 is false
    • Array(undefined) creates [undefined] → loop runs once
    • obj[undefined - 0 - 1] = obj[NaN] = obj["NaN"]
  3. The payload is only 37 bytes, easily bypassing nginx's 75-byte limit.
  4. The function returns null and the flag is revealed in the HTTP response.
